# 記事保存ロジックの形式モデル

`formal-verification/ArticleStore.lean` は記事保存処理の性質を記述する Lean 4 の小さなモデルです。依存は Lean 標準ライブラリのみで、`cd formal-verification && lake env lean ArticleStore.lean` で検証します。

## URL 重複除去

Lean の `List.eraseDups` をモデルとして、重複がないこと、入力の要素が失われないこと、非空入力が空にならないことを証明します。Lean のモデルは、`article-store.ts` の `Set` と順次追加するループが同じ結果を作ることまでは証明しません。その対応はレビューと `article-store.test.ts` の回帰テストで確認します。TypeScript の実装は先に現れた URL の記事を残します。

## バッチ分割

Lean モデルでは、1行あたりのカラム数が正であることを前提に、バインドパラメータ予算から求めた最大行数が予算を超えないことを証明します。`article-store.ts` は実際の挿入オブジェクトのキー数から使用可能行数を計算し、0件以下なら表明エラーにします。行配列をチャンクに分けたときの連結一致・順序保持そのものは Lean で直接証明していません。現在の対応は TypeScript の境界テスト（16件・17件）で検証します。

## 前提と差分

- D1 のパラメータ上限は100、コードでは80%の安全率を使います。
- 対象行は5列で、現在の上限は `floor(100 × 0.8 / 5) = 16` 行です。
- 証明対象は Lean のリストモデルと自然数の上限計算です。Drizzle、D1、TypeScript ランタイムの意味論やモデルと本番コードの同値性は対象外です。
- Lean 4 を使う学習・保守コストは、モデルを拡張してCIへ追加する前に評価してください。
